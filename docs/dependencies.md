### How the Create version was determined

1. Modrinth (`/v2/project/create/version?loaders=[neoforge]&game_versions=[1.21.1]`): latest **release** is `6.0.10+mc1.21.1`, published 2026-04-21.
2. GitHub tag `mc1.21.1-6.0.10` → commit `ac0c444d9828da3453ae8cc65338e8de063286fb`.
3. The Maven metadata contains many CI builds (`6.0.10-217` … `6.0.10-281`, `6.0.11-*`). The manifest `Git-Hash` of `6.0.10-280-slim.jar` equals the release tag commit. `6.0.10-281` is already a later commit. **→ `6.0.10-280` is the release build.**
4. Library versions (NeoForge minimum, Ponder, Flywheel, Vanillin, Registrate, Parchment) were copied from `gradle.properties` at that tag.

`6.0.11-*` builds exist on Maven but are unreleased dev builds, so they are not used.

### Why every Create artifact is `transitive = false`

The published Create POM declares its optional integrations as runtime dependencies: JEI, Curios, CC: Tweaked, Farmer's Delight, FTB Chunks/Teams/Library, JourneyMap, **Architectury**. Architectury is explicitly forbidden for this project, and none of the others are needed. Ponder's POM also pins Flywheel 1.0.4. Therefore Create and Ponder are non-transitive and the real requirements are listed explicitly.

In production, Create's full jar bundles Registrate, Ponder and Flywheel via JarJar, so Wareworks does **not** JarJar them itself.

## Known issues / notes

* Harmless dev-environment log warnings: `JarSelector: Attempted to select a dependency jar for JarJar which was passed in as source: flywheel`, `ponder.refmap.json could not be read`, `ApiStatus$ScheduledForRemoval` class not found.
* Harmless `runGameTestServer` / `runData` log lines: `[main/ERROR] ... Settings: Failed to load properties from file: server.properties` (the GameTest server has no server.properties), `Ambiguity between arguments [teleport, ...]` (vanilla Brigadier), `VanillaPackResourcesBuilder: Assets URL 'union:...' uses unexpected schema` (dev jar layout).
* Harmless vanilla `runClient` log lines: `SoundEngine: Missing sound for event: minecraft:item.goat_horn.play` / `minecraft:entity.goat.screaming.horn_break`, `ShaderInstance: Shader rendertype_entity_translucent_emissive could not find sampler named Sampler2`. Harmless `runServer` lines: the `OFFLINE/INSECURE MODE` block (dev server config) and `LanServerPinger: Invalid argument: sendto`.
* Harmless after a `mod_version` change, when a dev world saved by the previous version is loaded (`runServer`, `runClient`): `CommonHooks: The following mods have version differences that were not resolved: wareworks (version <saved> -> <loaded>)`. NeoForge compares the mod list stored in `level.dat` with the loaded mods (`CommonHooks#readAdditionalLevelSaveData`); the next world save writes the new version (`CommonHooks#writeAdditionalLevelSaveData`), so it is gone after one clean save.
* Expected `WARN` lines from `dev.wareworks.content.item.ItemKey` in the GameTest log (`Could not load item key from "garbage"`, `... wareworks:does_not_exist`): the `itemkeypersistence` and `controllerpersistence` tests feed invalid tags on purpose.
* Expected `WARN` lines from `dev.wareworks.content.station.StationBuffer` in the GameTest log (`Station buffer save holds more than 1024 stacks; N entries were not fully loaded`): `stationpersistence` loads crafted oversized counts on purpose.
* Expected `WARN` line from `dev.wareworks.content.crane.CraneExecution` in the GameTest log (`Stacker cranes cannot move: the server config sets [crane.travelBlocksPerTickPerRpm] to 0 ...`): `configzerospeedfactorpausescranes` sets that factor to 0 on purpose (M5). It is logged once per server run: the rate-limit flag is a class static that `content.crane.CraneServerHooks` resets on NeoForge's `ServerStartingEvent`, because a single-player client's JVM outlives every integrated server it starts.
* Expected `WARN` lines with stack traces (`IllegalStateException: test inventory fails at slot 2`) from `dev.wareworks.content.crane.head.TransferContexts` in the GameTest log (`Inventory at ... failed while extracting ...; keeping the N items it handed out before`, `... failed while inserting ...; N ... did not go in`): `craneheadsurvivesthrowinginventory` uses an inventory that throws part way through a transfer on purpose.
* Expected `WARN` lines from `dev.wareworks.content.crane.head.InventoryGrabber` (`Handling head save holds more than 16 item types or 4096 items; the rest was not loaded`) and from `dev.wareworks.content.crane.CraneExecution` (`Stacker crane at ... held 4096 items that belong to no job; dropped them at the dock`, `job ... expected 32 held items but the head holds 12; following the head`) in the GameTest log: `cranecraftedheadisboundedandspilled` and `cranejobfollowsacraftedhead` load crafted head data on purpose (M5 release audit).
* After a Wareworks update changes the config spec (new keys, but also only a changed comment), NeoForge logs once `Configuration file ...wareworks-server.toml is not correct. Correcting` and rewrites the file; existing values are kept. The line does not appear on the next start with the same spec.
* Create's version checker reports `OUTDATED Current: 6.0.10 Target: 6.0.10+mc1.21.1`. This is a version-string format mismatch, not an actual update.
* A dev run whose world was last saved with a different `mod_version` logs once `CommonHooks/WP: The following mods have version differences that were not resolved: wareworks (version X -> Y)`. Seen in a `runServer` run, because `run/server/world` was created while `mod_version` was briefly `0.1.0` before it was reverted to `0.1.0-alpha`. It is a property of the saved dev world (`run/` is gitignored), not of the mod or the release jar; deleting the dev world removes it.
* `runVisualTest` (dev tooling, ADR-014): the last pass leaves Flywheel's client config in `run/visual/config/flywheel-client.toml` at backend `off`; the next run selects `DEFAULT` again before its first pass, and other run directories are not affected. A failed run stops the game on purpose through a crash report (`run/visual/crash-reports/crash-*-client.txt`, description "Wareworks visual smoke test failed: ..."), so the Gradle task exits non-zero.
